## Audio

US uses en-US-AvaMultilingualNeural and UK uses en-GB-LibbyNeural, with one shared prosody/profile contract across the curriculum. Requests and audio response headers are verified; a mismatch fails visibly, with no browser speech-synthesis fallback.

`verify:voices` passed 480 items, 2,112 payloads and all 32 phonics button sets. The live report contains 54 strict-header MP3 results, including all three categories at levels 1/8/16/24/32, additional sampled levels and canonical same-text comparisons. All 54 reached browser playback completion at 1x without decoder errors or overlapping playback. This verifies delivery/playback and configured identity; it is not a human listening judgement about timbre or teaching quality. `voice-consistency-report.json` deliberately retains `listeningCompleted: false`.

## Production smoke test and follow-up

The first release, `01214a7fff3f47ed1f7eec37278472320d1a846c`, was published by Netlify deploy `6a9c47ce11caca0008c39ab7`. All 448 deployed illustrations and 11 principal code assets matched local SHA256; all illustration responses had immutable caching. Eleven expected pages returned 200 and an unknown path returned the custom 404. The production database matched every field of the 480 reviewed items and all 96 level goals, not just the counts.

The user logged into Teacher Studio and then the learner side. In production, saving the existing teacher settings returned `Saved ✓`; the allowed range stayed 1–4. The learner opened four levels and a direct Level 32 URL showed a locked page with no item content. Favouriting `book`, reloading, filtering Saved, answering its four-choice review and rating Good persisted across reload. Teacher Studio then showed one started/reviewed item, one repetition and one favourite. These single-item verification records remain visible; no historical learning data was deleted. The learner and teacher authentication sessions are separate.

The actual production Words, Phrases and Phonics Level 1 US/UK buttons were all played to the `Ready to play again` completion state (six additional plays, including both guided Phonics recordings). Production learner widths 390/834/1440 were checked with real backend data.

A subsequent verification found that a failed access check reused the intentional-account-pause message. The follow-up changes only the frontend explanation: a failed check or missing settings asks the learner to check connection/sign-in and retry, while a verified disabled account still says paused. Access continues to fail closed. Regression coverage exercises four failure forms, actual pause, recovery and anonymous preview. The text-quiz Japanese correct feedback was also made independent of whether the question used listening. The latest deployed child revision is available in `/release.json`.
